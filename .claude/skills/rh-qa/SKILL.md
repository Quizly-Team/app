# rh-qa, QA 단계

**실행 모드: 서브에이전트 위임.**

구현된 변경을 **세 관점**으로 검증한다. 산출은 `docs/ai/qa/<id>.md`. 코드 변경 없이 단독 감사로도 쓸 수 있다.

> **전제: 검증을 세 층으로 가르고 가장 싼 층부터 쓴다.**
>
> | 층 | 덮는 것 |
> | --- | --- |
> | 1. 단위 테스트 | 판정 함수, 파서, 포맷터, 계산 |
> | 2. 에뮬레이터와 시뮬레이터 | UI, 라우팅, 상태, REST, 인증, 파일 업로드 |
> | 3. 실기기 | 카메라, 실제 네트워크 품질, 발열, 스토어 배포 경로 |
>
> 1층으로 덮을 수 있는 것을 위로 올리면 `fail` 사유다.
>
> ⚠️ **`react-native` 를 import 하는 모듈은 1층으로 못 내린다.** vitest 가 RN 의 Flow 소스를 파싱하지 못한다. 그런 모듈이 순수 로직을 품고 있으면 "로직을 RN 비의존 모듈로 분리하라" 가 지적 사항이다.

## 절차

### 0. 스코프

`<id>` 를 파악하고 `docs/ai/plan/<id>.md` 의 통합 touchpoints 와 `git diff` 로 변경 표면을 정한다. 단독 감사 요청이면 diff 없이 지정 모듈 전체를 본다.

### 1. integration-qa 호출

**아키텍처**
`app/` to `features/` to `shared/` 단방향 유지, feature 간 직접 import 발생 여부, 네트워크 로직이 화면에 인라인으로 들어갔는지, barrel export 생성 여부, 빈 디렉터리 선생성 여부.

**통합 정합성 (양쪽 동시 읽기)**

| 경계 | 생산자 | 소비자 |
| --- | --- | --- |
| REST 응답 | 백엔드 컨트롤러와 Response 타입 | 앱의 제네릭과 타입 정의. **이름, 옵셔널 여부, 단위까지** |
| 에러 | 서버 `ErrorCode` 와 HTTP 상태 | 앱의 에러 분기 |
| 인증 | 서버 토큰 재발급 경로 | 앱의 401 처리. **한 곳에만.** 기존 웹은 3곳에 중복돼 기술부채가 됐다 |
| 디자인 토큰 | 웹 레포 `tokens/tokens.json` | 생성된 `theme.ts` 와 그걸 쓰는 화면 |
| 라우트 | expo-router 파일 트리 | 화면 간 이동 코드. 경로 문자열 직송은 리팩터에 깨진다 |
| 자원 | open (타이머, 구독, 파일 핸들) | dispose/cancel/close, 중간 이탈 경로 포함 |

서버 쪽은 `quizly-be-contract` 스킬의 조회 방법을 쓴다. **계획이나 리뷰의 "대조 완료" 서술을 믿지 말고 컨트롤러 원문을 직접 연다.** 기존 웹 클라이언트 코드를 서버 근거로 인용하지 않는다.

**체크리스트 작성 (태블릿 / 폰 분리)**
두 개로 나눠 쓴다. 공통으로 선행 조건, 번호 매긴 조작 순서, 단계별 기대 결과, 실패 시 볼 로그 위치를 적는다.

환경에 **선행 조건이 있으면 같이 적는다.** 못 돌리는 절차를 사람에게 넘기지 않는다 (환경 현황은 `integration-qa` 에이전트 문서의 표 참조. 폰 AVD 와 iOS 런타임이 아직 없다).

`adb` 로 확인 가능한 항목은 명령까지 적는다.

게이트는 `.claude/scripts/check-gate.sh`. **게이트가 PASS 인데 경계면이 어긋난 상황이 바로 이 단계가 존재하는 이유다.** 그런 경우를 리포트에 명시한다.

`verdict`(pass / fail)로 `docs/ai/qa/<id>.md` 에 쓴다. **모듈이 끝날 때마다 점진적으로** 돌린다. 경계면 오류가 뒤 모듈로 번지기 전에 잡아야 한다.

### 2. 루프

- `pass` -> 종료. Phase 2 도 통과면 사람에게 commit/PR 을 넘긴다
- `fail` -> rh-implement 재호출로 Critical 수정 -> 재검증. `pass` 까지 반복

## 하드 룰

- 경계면은 항상 **양쪽을 읽고** 판단한다. 한쪽만 인용한 지적은 미완이다.
- 존재 확인보다 교차 비교를 우선한다. "필드가 있다" 가 아니라 "양쪽 이름과 단위가 같다" 를 본다.
- 순수 로직에 테스트가 없으면 그 사실을 리포트에 적는다. 수동 체크리스트로 대체하지 않는다.
- 기본은 리포트와 수정 요청이다 (구현자가 코드를 소유해야 검증 독립성이 유지된다). 사용자가 명시할 때만 직접 수정한다.
- 절대 `git push` / `git commit` / `gh pr create` 를 하지 않는다.
- 산문은 한국어, 식별자와 경로는 영어. `—` 와 `·` 는 쓰지 않는다.
