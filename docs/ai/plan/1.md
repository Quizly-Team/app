## 1. Context

`src/shared/constants/theme.ts` 가 없다. 색, 간격, 라운딩, 타이포를 꺼낼 곳이 없어 이후 모든 화면 작업이 스타일 근거 없이 막혀 있다. CLAUDE.md 와 `quizly-app-conventions` 는 이 파일이 **생성물**이라고 전제하고 고정 px 와 하드코딩 색을 금지한다. 지금 상태로 화면을 만들면 규약을 지킬 방법 자체가 없다.

토큰 단일 소스는 웹 레포(`Quizly-Team/frontend`)의 `tokens/tokens.json` 이다. 디자이너는 피그마 Tokens Studio 에서 웹 레포로만 Push 한다 (설계 5.4). 이 작업은 그 JSON 을 RN 이 쓸 수 있는 `as const` 객체로 바꾸는 변환 스크립트, 그 생성물, 생성물을 고정하는 단위 테스트를 넣는다.

앱은 웹 브랜치를 따라가지 않고 **커밋 SHA 하나에 고정**해 받는다 (2026-11-27 사람 결정). 프론트의 lockfile 과 같은 역할이다. `dev` 를 따라가면 같은 명령이 날마다 다른 생성물을 내고, 관계없는 PR 에서 `tokens:build` 를 돌린 사람이 검토 안 된 토큰 변경을 섞어 넣게 된다.

세팅 계획(`docs/ai/2026-11-13-quizly-app-setup-plan.md`) Task 3 의 Step 1 부터 Step 3 까지가 이 작업이다. Step 4, 5(화면 적용과 3환경 레이아웃 검증)는 디자이너 확인 대기라 들어오지 않는다.

### Step 1: `scripts/build-tokens.mjs` 작성

입력 `https://raw.githubusercontent.com/Quizly-Team/frontend/${TOKENS_SHA}/tokens/tokens.json`, 출력 `src/shared/constants/theme.ts`. public 레포라 인증이 없다. full SHA 를 넣은 raw URL 이 200 을 주는 것은 실측했다 (planner, 2026-11-27).

`TOKENS_SHA` 는 스크립트 머리의 명명 상수 **한 개**이고 40자 full SHA 문자열이다. SHA 가 레포 안에 있는 곳은 이 상수와 생성물 머리 주석 두 곳뿐이다. 브랜치 이름을 쓰지 않는다 (2026-11-27 사람 결정).

0. **시작 SHA 를 읽는다 (구현 시점 1회).** 아래 명령의 출력 40자를 `TOKENS_SHA` 에 그대로 넣는다. 계획에는 값을 적지 않는다. 이 명령의 정본은 Step 7-2 가 `quizly-app-conventions/SKILL.md` 에 넣는 조회 블록이고, 아래는 그 첫 줄과 같다

   ```bash
   curl -fsS 'https://api.github.com/repos/Quizly-Team/frontend/commits?sha=dev&path=tokens/tokens.json&per_page=1' | node -p 'JSON.parse(require("fs").readFileSync(0, "utf8"))[0].sha'
   ```

   **인증 없이 돈다.** 4회차의 `gh api` 는 로그인 안 된 셸에서 `gh auth login` 안내를 내고 exit 4 다 (3회차 비평 실측). 같은 REST 조회를 `curl` 로 보내면 200 이다. planner 도 2026-11-27 에 위 명령을 인증 없이 돌려 `d9f0213` 으로 시작하는 40자를 받았다. JSON 은 `jq` 가 아니라 `node` 로 읽는다. Node 22 는 이 레포의 전제라 어느 셸에도 있다. HTTP 에러면 `curl -f` 가 죽고 `node` 가 빈 입력에 JSON 파싱 에러를 내며 0 이 아닌 코드로 끝난다 (없는 브랜치로 404 를 만들어 실측). 빈 값이 조용히 나오지 않는다. 인증 없는 REST 의 한도는 응답 헤더 `x-ratelimit-limit: 60` 이다 (planner 실측)

   ⚠️ 출력이 **`d9f0213` 으로 시작하지 않으면 멈추고 조정자에게 올린다.** 2026-11-27 기준 출력은 `d9f0213` 으로 시작했고(참고용), 이 계획의 숫자(Step 2, 3, 4, 5)는 전부 그 커밋의 `tokens.json` 에서 센 값이다. 다른 SHA 에서는 근거가 없다. 디자이너가 그 사이 재Push 했다는 뜻이므로(§6-14) `$type` 구성부터 다시 봐야 하고, 숫자를 생성물에 맞춰 고치는 것은 Step 4 의 금지 규칙에 걸린다
1. **SHA 가드와 fetch.** `TOKENS_SHA` 가 `/^[0-9a-f]{40}$/` 가 아니면 **fetch 전에** throw 한다. 누가 `"dev"` 나 짧은 SHA 를 넣으면 고정이 조용히 풀리기 때문이다. 그다음 fetch 하고 `res.ok` 가 아니면 상태 코드를 담아 throw 한다. `fetch` 는 404 에 throw 하지 않으므로 명시적으로 막는다. 응답을 `JSON.parse` 한다
2. **세트 재귀 병합.** 먼저 `$metadata.tokenSetOrder` 가 스크립트 머리의 명명 상수 `TOKEN_SET_ORDER` 와 순서까지 같지 않으면 throw 한다. 값은 `d9f0213` 의 9개 `global`, `[DS] Primitive/Value`, `[DS] Semantic/Light`, `[DS] Semantic/Dark`, `[DS] Typography/Value`, `[DS] Opacity/Value`, `[DS] Spacing/Value`, `[DS] Radius/Value`, `[DS] Layout/Value` 다 (planner 재실측 2026-11-27). 새 세트는 병합 트리에만 들어가고 출력으로 갈 길이 없어서 5번 가드에도 10번 요약에도 안 잡힌다 (4회차 비평 Minor 4). 5번과 같은 판단이고, 받을지는 SHA 를 올리는 PR 에서 사람이 정한다. 그다음 `tokenSetOrder` 순서로 돌고 `[DS] Semantic/Dark` 만 제외한다. 얕은 병합이면 Primitive 의 `gray` 그룹이 Semantic 의 `gray` 로 통째로 덮여 `{gray.800}` 참조가 안 풀린다. 병합 결과는 **참조 해석 전용 트리**이고 출력에 쓰지 않는다
3. **`deref`.** `{green.600}` `{line-height.3xl}` `{fontSize.13}` 을 병합 트리에서 실제 값으로 푼다. 웹의 `deref` 는 노드가 없으면 원래 문자열을 반환해서 `"{gray.800}"` 이 색 값으로 박히는데, 여기서는 **미해석 참조와 깊이 초과를 둘 다 throw 한다.** 깊이 한계는 스크립트 머리의 명명 상수 `DEREF_MAX_DEPTH = 6` 이다. 출처는 웹 `scripts/build-tokens.mjs:151` 의 `depth > 6` 이다 (3회차 비평 확인)
4. **출력 트리 수집.** 색과 타이포는 `[DS] Semantic/Light` **세트에서만** 순회한다. 원시 팔레트는 내보내지 않는다 (시맨틱 토큰을 우회하는 길이 생긴다). ⚠️ `[DS] Typography/Value` 는 **출력 대상이 아니다.** 그 세트는 `number` 42, `fontWeights` 4, `text` 1 의 원시 수치이고 2번 병합 트리로만 들어간다. `TYPOGRAPHY` 42개는 `[DS] Semantic/Light` 의 `$type: typography` 리프다 (조정자 실측)
5. **그룹 이름이 아니라 `$type` 으로 가른다.** `[DS] Semantic/Light` 리프 125개의 분포는 `color` 50, `typography` 42, `fontSizes` 14, `letterSpacing` 12, `boxShadow` 3, `paragraphSpacing` 1, `textCase` 1, `textDecoration` 1, `dimension` 1 이다 (조정자 실측). `COLORS` 는 `$type === "color"` 리프 50개, `TYPOGRAPHY` 는 `$type === "typography"` 리프 42개다. `shadow` 그룹이 두 타입을 걸치므로 **그룹 이름으로 제외하면 색 3개가 같이 사라진다** (§2, §6-12). 그리고 **`[DS] Semantic/Light` 리프의 `$type` 이 위 9개 밖이면 throw 한다.** 가드는 이 세트에만 건다. 병합 트리나 다른 세트에 걸면 `number`, `fontWeights`, `text` 가 9개 밖이라 지금 SHA 에서 즉시 throw 한다 (3회차 비평 Minor 2). 9개 이름은 스크립트 머리의 명명 상수 한 곳에 둔다. 지금 SHA 에서는 울리지 않는다. 디자이너가 재Push 한 토큰(§6-14)이 새 `$type` 으로 들어오면 3회차 설계는 그것을 출력에서 소리 없이 뺐고 테스트도 안 울렸다. 버릴지 변환할지는 SHA 를 올리는 PR 에서 사람이 정한다
6. **타이포 합성 토큰 해체.** `$type === "typography"` 노드의 `$value` 에서 `fontSize`, `lineHeight`, `letterSpacing`, `fontWeight` 를 각각 `deref` 한다. `fontWeight` 는 `"Bold" | "SemiBold" | "Medium" | "Regular" | "Light"` 를 `"700" | "600" | "500" | "400" | "300"` 으로 매핑하고 **매핑에 없는 값은 throw 한다.** 웹은 `?? 400` 으로 떨어뜨리는데 그러면 디자이너가 새 weight 를 넣은 날 전체 글자가 Regular 로 바뀐 걸 아무도 모른다. `fontFamily`, `paragraphSpacing`, `paragraphIndent`, `textCase`, `textDecoration` 은 버린다 (§2)
7. **간격 스텝 검증.** 가드 이름 `assertSpacingStep`, 임계값은 스크립트 머리의 명명 상수 `SPACING_STEP_PX = 2`. `v % SPACING_STEP_PX !== 0` 인 값이 하나라도 있으면 throw 하고 파일을 쓰지 않는다. 식의 의미는 Step 2
8. **스칼라 4세트.** `[DS] Spacing/Value`, `[DS] Radius/Value`, `[DS] Opacity/Value`, `[DS] Layout/Value` 를 각각 평평한 레코드로 만든다. `OPACITY` 만 `/100` 변환이 붙는다 (Step 3)
9. **파일 쓰기.** 검증을 모두 통과한 뒤 한 번만 쓴다. 중간에 throw 되면 기존 `theme.ts` 가 그대로 남는다. 부분 생성물이 커밋되는 경로를 만들지 않는다
10. 마지막에 개수를 한 줄 출력한다 (`colors 50, typography 42, spacing 12, ...`). 같은 줄에 **`[DS] Semantic/Light` 에서 출력하지 않고 버린 리프 수를 `$type` 별로** 찍는다. 지금 SHA 의 기준값은 `boxShadow 3, fontSizes 14, letterSpacing 12, paragraphSpacing 1, textCase 1, textDecoration 1, dimension 1` 이다 (planner 재실측 2026-11-27, 125 리프에서 `color` 50 과 `typography` 42 를 뺀 33). 5번 가드는 새 타입 이름만 막고, 기존 7종으로 들어온 새 리프는 소리 없이 빠지며 `theme.ts` diff 에도 안 보인다. SHA 갱신 PR 에서 `boxShadow 4` 가 찍히면 돌린 사람이 본다 (3회차 비평 Minor 1). **같은 줄을 생성물 머리 4행 주석으로도 쓴다** (Step 3). 콘솔만으로는 돌린 사람이 기준값 3 을 기억해야 한다. 머리에 있으면 SHA 갱신 PR 의 `theme.ts` diff 에 `boxShadow 3` 이 `4` 로 바뀐 것이 보인다 (4회차 비평 Minor 3). `console.log` 는 빌드 스크립트이고 앱 코드가 아니다

**토큰 이름을 변환하지 않는다.** `content-max`, `touch-min`, `text-3xl`, `2xl`, `key-strong` 모두 원문 그대로 키가 된다. camelCase 로 바꾸면 변환 표를 영구히 유지해야 하고 토큰 이름으로 코드를 grep 할 수 없다. 식별자로 못 쓰는 키는 `JSON.stringify` 로 따옴표를 씌운다. 소비 측은 `LAYOUT["touch-min"]`, `TYPOGRAPHY["text-1rg"].regular` 로 쓴다.

검증: `node scripts/build-tokens.mjs` 가 exit 0 이고 `theme.ts` 가 생긴다. 생성물을 `/tmp/theme.1.ts` 로 복사하고 한 번 더 돌려 `cmp /tmp/theme.1.ts src/shared/constants/theme.ts` 가 exit 0 이다 (출력이 결정적이다. SHA 고정으로 입력 바이트도 고정됐다). ⚠️ 3회차의 `git diff --exit-code` 는 쓰지 않는다. 첫 생성 시점의 `theme.ts` 는 untracked 라 `git diff` 가 비교 대상을 갖지 않고 무조건 exit 0 이다.

### Step 2: 간격 스텝 가드의 실제 의미 (판단 지점 2)

`[DS] Spacing/Value` 전체는 `2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80` 12개다 (조정자 실측). **`2` 만 4의 배수가 아니고 나머지 11개는 전부 4의 배수다.** 엄격한 `v % 4 !== 0` 을 쓰면 `2` 때문에 빌드가 즉시 선다. `spacing.2` 는 `$description` 이 "줄 간격 등 광학 보정 전용" 이고 디자이너가 의도적으로 넣은 반 스텝이다. 그래서 **통과 집합은 웹과 같게 유지한다.** 멈추는 이유가 디자인 결함이 아니라 우리가 식을 바꾼 것이 되면 잘못된 실패다.

바꾸는 것은 식이 아니라 이름과 상수다.

- 웹 식 `((v / 4) * 2) % 1 !== 0` 은 정수 `v` 에서 `v % 2 !== 0` 과 통과/실패 집합이 같다. 손으로 확인했다 (`2` 통과, `3` FAIL, `6` 통과, `10` 통과, `18` 통과)
- 그래서 `v % SPACING_STEP_PX !== 0` 로 쓴다. `SPACING_STEP_PX = 2`, 주석은 "2px 단위를 허용한다. `spacing.2` 가 의도된 반 스텝이다 (§6-8)"
- `assert4pxGrid` 류 이름을 쓰지 않는다. 이름이 하지 않는 일을 주장하면 다음 사람이 이 가드를 믿는다
- 상수를 `src/shared/constants/` 로 빼지 않는다. 소비자가 이 스크립트 하나이고 앱 코드가 아니다

이 가드에 단위 테스트를 붙이지 않는다. 스크립트 안의 6행 가드이고 생성물 쪽 `SPACING` 값 고정 테스트가 같은 사실을 들고 있다. `2` 가 통과하고 `3` 이 걸리는지는 스크립트를 짜는 동안 한 번 손으로 확인한다. 통과 집합의 구멍은 §6-8 이다.

### Step 3: `theme.ts` export 모양

### Step 4: `src/shared/constants/theme.test.ts` 작성

`react-native` 를 **값으로 import 하지 않는다.** 타입만 `import type { TextStyle } from "react-native"` 로 가져온다. 타입 전용 import 는 esbuild 가 완전히 지워서 vitest 가 RN 의 Flow 소스를 건드리지 않는다 (실측 확인).

테스트의 목적은 하나다. **생성 스크립트가 조용히 망가진 생성물을 커밋하는 경로를 막는다.** `COLORS` 가 `{}` 로 나와도 `as const` 빈 객체는 typecheck 와 oxfmt 를 전부 통과하므로 테스트가 유일한 방어선이다. 그래서 6개 export 전부에 단언이 하나 이상 있다.

🚫 **기대값은 `TOKENS_SHA` 의 `tokens.json` 에서 센 값으로 적는다. 세지 못하면 그 단언을 넣지 않는다. 생성된 `theme.ts` 를 보고 기대값을 적는 것은 금지다.** 자기 자신을 참조하는 테스트는 영구히 초록이다. 아래 숫자는 전부 `d9f0213` 의 `tokens.json` 에서 센 값이다. 이 규칙은 이후 SHA 를 올리는 PR 에도 그대로 적용된다 (Step 6).

테스트 7개다.

1. `Object.values(SPACING)` 가 `[2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80]` 과 같다
2. `RADIUS` 를 `toEqual` 로 고정한다 (8키, Step 3 의 값)
3. `OPACITY` 의 모든 값이 0..1 이고 `OPACITY["14"] === 0.14`, `OPACITY["100"] === 1`. 퍼센트가 다시 새어 들어오면 여기서 걸린다
4. `TYPOGRAPHY["text-1rg"].regular` 를 `TextStyle` 변수에 대입하고 `{ fontSize: 16, lineHeight: 24, letterSpacing: -0.06, fontWeight: "400" }` 로 고정한다. **대입 자체가 타입 검증**이다. `fontWeight` 가 `string` 으로 넓어지면 `tsc` 가 여기서 깨진다
5. **`TYPOGRAPHY` variant 리프 개수가 42 다.** 4번의 1개 샘플로는 해체 로직이 variant 하나를 떨어뜨리는 사고가 안 잡힌다. 최상위 키는 `text-3xl` 부터 `text-1xs` 까지 14 개다 (planner 재실측 2026-11-27, 3회차 비평 Minor 6). 최상위 키 개수 단언은 **넣지 않는다.** 이유는 §6 의 반영하지 않은 지적
6. **`COLORS` 를 고정한다.** `$type: color` 리프 개수 `50`(4행짜리 재귀 카운터)과 최상위 그룹 개수 `12` 다. 그리고 대표 값을 고정한다. 2단 `COLORS.primary.normal === "#30a10e"`, 8자리 hex `COLORS.fill.assistive === "#5555550f"`, 3단 리터럴 `COLORS.interaction.primary.pressed === "#30a10e24"`. 3단 **참조**인 `COLORS.status.positive.normal`(`$value` 가 `{blue.500}`)은 deref 결과 `"#2473fc"` 로 고정한다. 이 값은 `d9f0213` 의 `[DS] Primitive/Value` `blue.500` 을 planner 가 직접 읽은 것이다 (2026-11-27). 생성물에서 베끼지 않았다. 세트가 통째로 비는 사고는 개수 단언이 가장 싸게 잡고, 참조가 안 풀린 사고는 이 값 단언이 잡는다. **리프 50 단언이 `shadow` 그룹을 통째로 걸러내는 구현 실수(47)도 같이 잡는다** (§6-12)
7. **`LAYOUT` 전체를 `toEqual` 로 고정한다** (Step 5)

세팅 계획 Task 3 Step 2 의 "간격 스케일은 단조 증가한다" 테스트는 **넣지 않는다.** `SPACING` 키가 정수형 문자열이라 JS 가 항상 오름차순으로 열거하고 그 단언은 무조건 통과한다 (실측 확인). 값을 통째로 고정하는 1번이 같은 사실을 실제로 검사한다.

검증: `npx vitest run src/shared/constants/theme.test.ts` 가 전부 통과하고 `expected fail` 이 0 이다.

### Step 5: `touch-min` 44 미결을 테스트로 표현한다 (판단 지점 3)

**결론: 현재 토큰 값을 고정한다. `it.fails` 를 쓰지 않는다.**

```ts
// touch-min 목표는 44 (Apple HIG) 이고 현재 토큰은 40 이다. 미결은 §6-1.
// TOKENS_SHA 를 올렸는데 토큰이 44 이상이면 이 테스트가 깨진다. 그때 44 하한 단언으로 교체하고 이 주석을 지운다.
it("LAYOUT 이 토큰 현재값을 유지한다 (touch-min 40, 플랫폼 하한 44 는 미결)", () => {
  expect(LAYOUT).toEqual({
    "content-max": 1200,
    "readable-max": 840,
    panel: 420,
    "touch-min": 40,
  });
});
```

세 가지를 동시에 만족한다. (1) **게이트 절대 0건** 이다. 현재 토큰에서 `vitest run` exit 0 이고 베이스라인도 `--passWithNoTests` 도 안 쓴다. (2) **생성 고장을 삼키지 않는다.** `touch-min` 키가 사라져 `undefined` 가 되면 `toEqual` 이 즉시 FAIL 한다. (3) **미결이 코드에서 안 사라진다.** 44 가 테스트 이름에 문자 그대로 남아 한 줄만 읽어도 40 이 현재값이고 44 가 목표이며 미결임을 안다. 디자이너가 토큰을 44 로 올리고 그 커밋으로 `TOKENS_SHA` 를 올리는 PR 에서 이 테스트가 깨진다. 그때 할 일은 그 PR 안에서 생성물 갱신 + `toBeGreaterThanOrEqual(44)` 교체 + Step 7-1 의 네 문서 재수정이다.

검토한 대안과 버린 이유다.

| 대안 | 왜 버리는가 |
| --- | --- |
| `it.fails("...44...")` | 던져진 이유를 가리지 않는다. 생성이 깨져 `undefined` 가 되어도 `1 expected fail` 로 exit 0 이다. CLAUDE.md 의 "실패를 조용히 삼키는 것" 에 걸리고 Step 1 의 3번과 6번에서 조용한 통과를 throw 로 바꾼 판단과 자기모순이다 |
| `toBeGreaterThanOrEqual(44)` 를 그냥 실패하게 둔다 (세팅 계획 원안) | 게이트가 영구히 FAIL 이다. 베이스라인을 둘 수 없으니 이후 모든 이슈가 빨간 게이트 위에서 돌고 두 번째 FAIL 이 생겨도 아무도 못 알아챈다. **사람이 검토하고 기각했다** (2026-11-13 결정 (a)). 포기한 것은 §6-9 |
| 앱에 `TOUCH_MIN_FLOOR = 44` 를 둔다 | 토큰 단일 소스가 깨진다. 충돌 자체는 §6-1 로 올린다 |
| `it.skip` / `it.todo` | 영구히 눌러둔 알람이다. 토큰이 올라가도 아무 일이 안 일어난다 |

### Step 6: `package.json` 과 게이트의 관계 (판단 지점 1)

`package.json` scripts 에 `"tokens:build": "node scripts/build-tokens.mjs"` 한 줄만 추가한다. **`check-gate.sh` 를 고치지 않는다.**

| 질문 | 결론 | 근거 |
| --- | --- | --- |
| 게이트가 `tokens:build` 를 돌려야 하나 | **아니다** | 게이트는 네트워크 없이 돌아야 한다. 넣으면 비행기에서, CI 레이트 리밋에서, 웹 레포가 잠깐 안 열릴 때 `typecheck` 와 무관한 이유로 FAIL 한다. 한 번 신뢰를 잃은 게이트는 아무도 안 본다 |
| `theme.ts` 를 커밋하나 | **한다** | CLAUDE.md 와 `quizly-app-conventions` 가 이미 전제한다. clone 한 사람이 네트워크 없이 `npm test` 를 돌릴 수 있어야 하고, `theme.test.ts` 가 import 하므로 안 커밋하면 게이트가 못 돈다 |
| drift 를 검출하나 | **아니다** | SHA 고정 뒤로 `tokens:build` 는 drift 와 무관하다. 같은 SHA 는 같은 바이트를 주므로 몇 번을 돌려도 같은 생성물이 나온다. drift 는 "웹의 최신 SHA 가 `TOKENS_SHA` 와 다르다" 이고, 그걸 보려면 네트워크를 타야 해서 게이트에 넣을 수 없다. 자동화는 일일 워크플로(§2)이고 나중 작업이다 |

**SHA 를 올리는 이후 PR 의 순서.** 2026-11-27 사람 결정으로 SHA 갱신은 그것만 바꾸는 별도 PR 이다. 이 작업의 범위는 아니지만, 이 계획이 만든 테스트와 가드가 그 PR 에서 울리므로 할 일을 여기 적고 Step 7-2 가 정본 문서에 옮긴다.

1. `quizly-app-conventions/SKILL.md` 디자인 토큰 절의 조회 블록(Step 7-2) 첫 줄로 최신 SHA 를 읽어 `TOKENS_SHA` 한 줄만 바꾼다. 둘째 줄로 `design-tokens` 가 `dev` 보다 앞서 있는지 본다 (§6-13)
2. `npm run tokens:build`. 모르는 세트나 모르는 `$type` 이면 여기서 throw 한다 (Step 1 의 2번, 5번). 버릴지 변환할지 사람이 정한다
3. 게이트가 깨지면 `theme.test.ts` 기대값을 **새 SHA 의 `tokens.json` 을 세어** 고친다. 생성물에서 베끼지 않는다 (Step 4). `touch-min` 이 44 이상이면 Step 5 의 교체를 한다
4. PR 의 diff 는 `scripts/build-tokens.mjs` 의 SHA 한 줄, `theme.ts`, `theme.test.ts` 뿐이다. 다른 변경을 섞지 않는다. 예외는 3번의 `touch-min` 교체가 부르는 Step 7-1 문서 재수정이다

값이 바뀐 사실과 이유를 PR diff 에서 사람이 본다. drift 를 자동으로 못 보는 대가는 §6-7 이다.

검증: `npm run tokens:build` 가 네트워크를 끊은 상태에서 명확한 에러로 죽고 `theme.ts` 는 그대로 남는다. `.claude/scripts/check-gate.sh` 는 네트워크를 끊은 상태에서 `PASS` 다.

  - 모든 검사는 **실패할 때만 한 줄을 찍는다.** 없어야 하는 것은 `grep -q ... && echo "FOUND ..."`, 있어야 하는 것은 `grep -q ... || echo "MISSING ..."` 이다. `! grep -q` 와 맨 `[ ... ]` 꼴을 다시 넣지 않는다. 실패해도 아무것도 찍지 않고, bash 는 `!` 로 뒤집은 파이프라인 실패에 `set -e` 도 걸지 않는다 (3회차 비평 C4 재현)

### 수동 확인

**이 작업에는 화면 변경이 없다.** `src/app/index.tsx` 를 건드리지 않으므로 에뮬레이터에서 보이는 화면이 전과 동일하고, 생성물이 유효한 TS 인지는 `npm run typecheck` 가 이미 본다. 그래서 수동 확인은 **알람이 실제로 울리는지** 보는 다섯 단계만 둔다. 되돌리기는 전부 `npm run tokens:build` 재실행이다. 첫 생성 시점의 `theme.ts` 는 untracked 라 `git checkout` 으로 못 되돌린다.

1. `npm run tokens:build` → `src/shared/constants/theme.ts` 가 생기고 콘솔에 `colors 50, typography 42` 와 버린 리프 `boxShadow 3, fontSizes 14, letterSpacing 12, paragraphSpacing 1, textCase 1, textDecoration 1, dimension 1` 을 포함한 요약 한 줄이 뜬다 (Step 1 의 10번). 머리 2행에 40자 SHA, 머리 4행에 콘솔과 같은 요약 줄이 보인다. `cp src/shared/constants/theme.ts /tmp/theme.1.ts` 로 기준본을 둔다
2. `scripts/build-tokens.mjs` 의 `TOKENS_SHA` 를 임시로 `"dev"` 로 바꿔 `npm run tokens:build` → 0 이 아닌 코드로 죽고 메시지에 SHA 형식이 틀렸다는 내용이 보인다. 요청이 나가기 전에 죽으므로 네트워크 에러가 아니다. `cmp /tmp/theme.1.ts src/shared/constants/theme.ts` 가 exit 0. 상수를 원래 값으로 되돌린다
3. 네트워크를 끊고 `npm run tokens:build` → 0 이 아닌 코드로 죽고 메시지에 URL 또는 네트워크 실패 사유가 보인다. `cmp /tmp/theme.1.ts src/shared/constants/theme.ts` 가 exit 0
4. 네트워크를 끊은 채 `.claude/scripts/check-gate.sh` → `PASS`
5. 생성물을 임시로 하나씩 망가뜨리고 매번 `npx vitest run src/shared/constants/theme.test.ts` 를 돌린다. 한 번 돌릴 때마다 `npm run tokens:build` 로 되돌린다
   - `LAYOUT` 의 `touch-min` 을 `44` 로 → Step 5 테스트가 **FAIL** 하고 이름에 44 가 보인다
   - `LAYOUT` 을 `{}` 로 → Step 5 테스트가 **FAIL** 한다
   - `COLORS` 를 `{}` 로 → Step 4 의 6번 테스트가 **FAIL** 한다
   - 끝나면 `cmp /tmp/theme.1.ts src/shared/constants/theme.ts` 가 exit 0

⚠️ **AVD 로 앱을 띄우는 단계를 두지 않는다.** `theme.ts` 를 import 하는 앱 코드가 0 개라 Metro 가 번들에 넣지 않는다. 앱이 멀쩡히 뜨는 것은 파싱됐다는 증거가 아니라 **읽히지 않았다는 증거**다. 번들 파싱을 정말 확인하려면 화면이 `theme.ts` 를 실제로 import 해야 하고, 그것은 §2 가 범위 밖으로 뺀 화면 적용 작업이다. 그 작업에서는 폰 AVD 생성과 `xcodebuild -downloadPlatform iOS` 가 선행 조건으로 남는다 (CLAUDE.md 실측).
